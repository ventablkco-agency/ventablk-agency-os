# VentaBlk Co. — Agency Operating System

This repository is the source of truth for how VentaBlk Co. runs hospital website projects, from first contact and onboarding through design, development, launch, maintenance, and client offboarding.

## How to use this repository

- **Start here:** `PROGRESS.md` for current status and the exact next step.
- **Client lifecycle:** `CLIENT_LIFECYCLE.md` for the end-to-end workflow.
- **Design rules:** `design.md` for visual design principles, responsive behavior, and design handoff requirements.
- **Decisions:** `DECISIONS.md` for approved decisions and rationale.
- **Checklists:** `CHECKLIST.md` for stage gates and quality checks.
- **Templates:** `templates/` for reusable client-facing and internal documents.

## Working rules

- Work in small, agreed steps.
- Update documentation after each meaningful decision or completed task.
- Never assume a feature, integration, permission, or deployment is complete until verified.
- Keep credentials and private/patient data out of this repository.

## Initial scope

Build the agency's repeatable operating process first. Then standardize the hospital website starter, backend/form patterns, QA, deployment, maintenance, and offboarding based on verified needs.
